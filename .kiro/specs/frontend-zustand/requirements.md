# frontend-zustand Requirements

## 概要

フロントエンドで定例→作成→広報の進行状態を1つのクライアント状態で共有し、リロードや画面移動で失われないようにするための Zustand 基盤を導入する。

## 対象ユーザー

- StepByCode 運営メンバー（Web UI 利用者）
- フロントエンド開発者

## 対象ユースケース

1. 定例日時と Meet リンクを入力し、他画面でも同じ値を参照できる
2. 作成・広報の進行ボードが同じクライアント状態を読み書きできる
3. ブラウザリロード後も進行状況と入力済みテキストを保持する
4. 状態を開発時にリセットできる

## 成功条件

- Zustand store が `frontend/src/store` に整備され、Meeting/Publicity で共通利用される
- 永続化を含む状態を1か所で定義し、UI から同じ selector で参照できる
- 初期データは従来 UI と同じ見た目・挙動を維持する
- README に利用方法が追記される

## 非対象

- API 接続・実データ保存
- 権限判定やサーバーサイド状態管理
